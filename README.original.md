# Storage Health Monitor

A self-hosted dashboard for tracking SSD/HDD/USB drive health (SMART data,
bad-sector counts, temperature, wear level) over time.

**Why an agent instead of pure PHP/browser?** A web browser cannot read raw
disk hardware — that's an OS-level permission. So the actual scanning is done
by a small local script (`agent/`) using `smartctl`, and it POSTs results to
the PHP backend, which stores history and shows it on a dashboard.

## Setup (automated — no manual file copying)

Requirements: XAMPP installed and running (Apache + MySQL started), and
Node.js installed for the scanning agent.

**macOS / Linux:**
```bash
chmod +x setup.sh
./setup.sh
```

**Windows (PowerShell):**
```powershell
Set-ExecutionPolicy -Scope Process Bypass   # only needed once, if scripts are blocked
.\setup.ps1
```

The script will:
1. Find (or ask for) your XAMPP `htdocs` folder and copy the web app there.
2. Generate a fresh random API key.
3. Import the database, with that key baked in — you're prompted for your
   MySQL username/password (XAMPP defaults: `root` / blank).
4. Write your DB credentials into the deployed `config.php` automatically.
5. Write `agent/config.json` automatically, already pointed at your server
   with the matching API key — nothing to edit by hand.
6. Install the agent's Node dependencies (`npm install`) if Node is present.
7. Warn you if `smartctl` (smartmontools) isn't installed yet, since that's
   the actual tool that reads SMART data — it's a separate OS-level install
   the script can't do for you (see below).

When it finishes, open **http://localhost/storage-health-monitor/** — you
should see an empty dashboard ready to receive scans.

## Installing smartmontools (one-time, per machine you'll scan)

This is the only manual step, because it needs OS-level installer access
the setup script doesn't have:

- **Windows:** download from smartmontools.org and add it to your PATH
- **macOS:** `brew install smartmontools`
- **Linux:** `sudo apt install smartmontools` (or `dnf`/`yum` equivalent)

## If you installed the project as `A-Checker`

If your XAMPP URL is `http://localhost/A-Checker/`, the agent endpoint must be:
`http://localhost/A-Checker/php/api/report.php`.
Do not leave the generated endpoint pointing at `/storage-health-monitor/` after renaming the XAMPP folder.

If you imported `database/schema.sql` manually, the API key must match `agent/config.json`. The default development key in this package is `__API_KEY__`; for production, use the setup script to generate a random key.

## Running a scan

From the `agent` folder, on any machine you want monitored (config.json is
already set up by the installer):

```bash
# Windows (as Administrator)
npm run scan

# macOS/Linux
sudo npm run scan
```

Reading SMART data requires admin/root privileges, same as any native disk
tool. Scanning a different machine than the one running XAMPP? Edit
`agent/config.json` → `serverUrl` to use that machine's LAN IP instead of
`localhost`.

To scan automatically on a schedule, use **Task Scheduler** (Windows) or
**cron** (Linux/macOS), e.g. daily at 3am:
```
0 3 * * * cd /path/to/agent && npm run scan >> scan.log 2>&1
```

## USB flash drives / SD cards

These often don't expose standard SMART data, so the agent may report
nothing useful for them. A surface read/write verification tool (like
H2testw or F3) is more reliable for those — this project focuses on drives
that do report SMART (internal SATA/NVMe SSDs, HDDs, many external USB
enclosures).

## Project structure

```
storage-health-monitor/
├── setup.sh / setup.ps1      # Automated installers (run one of these)
├── database/schema.sql       # MySQL schema (API key filled in by installer)
├── php/
│   ├── config.php            # DB credentials (filled in by installer)
│   ├── db.php                # PDO connection helper
│   ├── index.php             # Dashboard (all drives)
│   ├── device.php            # Per-drive scan history
│   ├── api/report.php        # Agent POSTs scan results here
│   ├── api/devices.php       # JSON listing (optional, for custom UI)
│   └── assets/style.css
└── agent/
    ├── agent.js               # Runs smartctl, posts results
    ├── package.json
    └── config.json            # Generated by the installer (git-ignore this)
```

## Re-running setup

Safe to run again — it will re-copy the app files and generate a new API
key/database entry each time. If you've already got scan history you want
to keep, skip re-running the installer and just reuse the existing
`agent/config.json`.


## Advanced edition

This version keeps the original SMART architecture but adds:
- Health score (0-100) derived from SMART warnings and SSD wear.
- SMART self-test status and additional SMART flags.
- Windows partition/volume inventory via PowerShell (`Get-Partition` / `Get-Volume`).
- Linux partition inventory via `lsblk`.
- Partition size/free-space/usage/filesystem/label/health history in MySQL.
- Dashboard search, status filtering and 10-row pagination.
- Drive detail history graph and expanded SMART history.
- JSON API with partition summaries.
- Read-only partition management UI.

### About the HDSentinel-inspired design
The feature set is inspired by publicly documented concepts from Hard Disk Sentinel: health/performance monitoring, temperature and SMART values, history, alerts/tests and partition information. It does not copy HDSentinel code or proprietary implementation. HDSentinel documents real-time health/temperature/SMART monitoring, history, tests and partition information on its official site.

### Partition safety
The web partition manager is intentionally **read-only**. It does not expose format, delete, resize, initialize, or destructive surface-test commands through the browser. Those operations can cause data loss and should be performed with an explicit local Windows disk-management tool after backups.

### Recent cleanup (this build)
- Removed the partition-manager buttons that only *looked* like they could modify a disk (Create, Resize, Extend, Split, Merge, Format, Change Letter, File System Check, Clone, GPT/MBR Convert, BitLocker, Delete). They never executed anything server-side — clicking them just wrote a fake "queued" message to a log — so they were confusing UI clutter on a tool that's read-only by design. The partition panel now only offers **Refresh** and **Properties**, plus a note pointing to a real local disk tool if someone actually needs to change a partition.
- Scan Storage no longer uses a CAPTCHA. Scanning is treated as a read-only monitoring operation: the user sees a clear safety confirmation and can start the scan directly. If future features are added that modify, delete, format, resize, move, or otherwise change storage data, those destructive operations should use a separate explicit confirmation flow appropriate to the action.
## Connected Device Center

The dashboard now includes a left device sidebar for: **Storage, Printers, RAM, Smartphones (Android/iOS), and Other Devices**. The local agent reports hardware inventory every realtime cycle.

- **Storage:** SMART health, temperature, partitions and capacity.
- **Printers:** Windows `Get-Printer` or Linux/macOS `lpstat` when available.
- **RAM:** total, used and available system memory.
- **Smartphones:** Android devices through `adb` and iOS devices through `idevice_id` when those optional tools are installed.
- **Other:** reserved for additional hardware inventory.

All inventory collection is read-only. Optional Android/iOS bridges are detected only when their command-line tools are available.


## Advanced Device Center

The Device Center performs read-only hardware inventory. The local agent refreshes approximately every 5 seconds and reports connected storage, printers, RAM, Android/iOS devices, USB/Bluetooth/HID peripherals, network hardware, audio/display/camera hardware, and other operating-system devices.

### Read-only File Browser

The web dashboard includes a File Browser that can list approved local storage roots and folders and preview text files up to 1 MB. It does not provide upload, write, rename, delete, execute, or download operations. Paths are validated against the configured roots.

Set `ATESTCHECKER_FILE_ROOTS` to a semicolon-separated allowlist if you want to restrict browsing further. Example on Windows: `C:\Users;D:\Shared`.
