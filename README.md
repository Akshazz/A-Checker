# Storage Health Monitor

A self-hosted dashboard for tracking SSD/HDD/USB drive health (SMART data,
bad-sector counts, temperature, wear level) over time.

**Why an agent instead of pure PHP/browser?** A web browser cannot read raw
disk hardware — that's an OS-level permission. So the actual scanning is done
by a small local script (`agent/`) using `smartctl`, and it POSTs results to
the PHP backend, which stores history and shows it on a dashboard.

## Setup (automated — no manual file copying)

Requirements: XAMPP installed and running (Apache + MySQL started), and
Node.js installed for the scanning agent.

**macOS / Linux:**
```bash
chmod +x setup.sh
./setup.sh
```

**Windows (PowerShell):**
```powershell
Set-ExecutionPolicy -Scope Process Bypass   # only needed once, if scripts are blocked
.\setup.ps1
```

The script will:
1. Find (or ask for) your XAMPP `htdocs` folder and copy the web app there.
2. Generate a fresh random API key.
3. Import the database, with that key baked in — you're prompted for your
   MySQL username/password (XAMPP defaults: `root` / blank).
4. Write your DB credentials into the deployed `config.php` automatically.
5. Write `agent/config.json` automatically, already pointed at your server
   with the matching API key — nothing to edit by hand.
6. Install the agent's Node dependencies (`npm install`) if Node is present.
7. Warn you if `smartctl` (smartmontools) isn't installed yet, since that's
   the actual tool that reads SMART data — it's a separate OS-level install
   the script can't do for you (see below).

When it finishes, open **http://localhost/storage-health-monitor/** — you
should see an empty dashboard ready to receive scans.

## Installing smartmontools (one-time, per machine you'll scan)

This is the only manual step, because it needs OS-level installer access
the setup script doesn't have:

- **Windows:** download from smartmontools.org and add it to your PATH
- **macOS:** `brew install smartmontools`
- **Linux:** `sudo apt install smartmontools` (or `dnf`/`yum` equivalent)

## Running a scan

From the `agent` folder, on any machine you want monitored (config.json is
already set up by the installer):

```bash
# Windows (as Administrator)
npm run scan

# macOS/Linux
sudo npm run scan
```

Reading SMART data requires admin/root privileges, same as any native disk
tool. Scanning a different machine than the one running XAMPP? Edit
`agent/config.json` → `serverUrl` to use that machine's LAN IP instead of
`localhost`.

To scan automatically on a schedule, use **Task Scheduler** (Windows) or
**cron** (Linux/macOS), e.g. daily at 3am:
```
0 3 * * * cd /path/to/agent && npm run scan >> scan.log 2>&1
```

## USB flash drives / SD cards

These often don't expose standard SMART data, so the agent may report
nothing useful for them. A surface read/write verification tool (like
H2testw or F3) is more reliable for those — this project focuses on drives
that do report SMART (internal SATA/NVMe SSDs, HDDs, many external USB
enclosures).

## Project structure

```
storage-health-monitor/
├── setup.sh / setup.ps1      # Automated installers (run one of these)
├── database/schema.sql       # MySQL schema (API key filled in by installer)
├── php/
│   ├── config.php            # DB credentials (filled in by installer)
│   ├── db.php                # PDO connection helper
│   ├── index.php             # Dashboard (all drives)
│   ├── device.php            # Per-drive scan history
│   ├── api/report.php        # Agent POSTs scan results here
│   ├── api/devices.php       # JSON listing (optional, for custom UI)
│   └── assets/style.css
└── agent/
    ├── agent.js               # Runs smartctl, posts results
    ├── package.json
    └── config.json            # Generated by the installer (git-ignore this)
```

## Re-running setup

Safe to run again — it will re-copy the app files and generate a new API
key/database entry each time. If you've already got scan history you want
to keep, skip re-running the installer and just reuse the existing
`agent/config.json`.
